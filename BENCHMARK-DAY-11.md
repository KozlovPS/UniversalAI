# День 11 — модель памяти ассистента

Реализация: VERIFIED_OFFLINE. Реальное измерение: COMPLETED, 2026-11-21. Исходное условие: D:/Codex/MyProjects/UniversalAI/DAYS.md, раздел «День 11». Карточка: D:/Codex/MyProjects/UniversalAI/Tasks/Day-11/TASK.MD.

## Что показывает эксперимент

Три слоя существуют независимо: краткосрочная история текущего диалога, рабочие данные задачи и долговременные facts на основе Дня 10. В режиме Layered запись рабочей/долговременной памяти выполняется явным действием пользователя; модель не переносит туда весь разговор автоматически.

| Слой | Хранение обычного чата | Правило включения в промпт |
|---|---|---|
| Краткосрочный | ChatMessages, отдельно от записей задачи/facts | Последние Keep сообщений, с целостностью tool-хода; текущий пользовательский запрос добавляется отдельно |
| Рабочий | Conversation.WorkingMemoryJson | Все явно сохранённые ключи текущей задачи; пустой объект не создаёт сообщения |
| Долговременный | Conversation.FactsJson — словарь Sticky Facts Дня 10 | Все явно сохранённые facts; пустой объект не создаёт сообщения |

Порядок контекста: системная инструкция → долговременные facts → рабочая память → недавние сообщения → текущий вопрос. Неактивный summary не включается. При выключенной памяти действует прежний режим полной истории, без рабочей и долговременной памяти. Facts и данные задачи принадлежат выбранному диалогу; глобальные профили пользователей в этот день не входят.

## Автоматический сценарий

Контрольный набор фиксирован, пользовательские диалоги не изменяются. Один проход, 4 этапа × 6 независимых вопросов = 24 вызова выбранной модели. Генерация сценария и автоматическое извлечение фактов моделью не нужны.

| Слой | Явно помещённые данные | Контрольные вопросы |
|---|---|---|
| Диалог | Код СОСНА-731, переговорная ВЕГА-42 | Какой временный код встречи? В какой переговорной текущая встреча? |
| Задача | Экспорт TSV, задача LAB-118 | Какой формат экспорта выбран для текущей задачи? Какой номер текущей задачи? |
| Facts | Марина Соколова, бюджет 420000 | Как зовут ответственного за приёмку? Какой утверждённый бюджет в рублях? |

1. `all`: заполнить все три слоя, задать 6 вопросов — ожидаются все значения.
2. `clear-short`: удалить только краткосрочную историю; код и переговорная становятся НЕИЗВЕСТНО, остальные значения доступны.
3. `clear-working`: дополнительно удалить данные задачи; экспорт и номер задачи становятся НЕИЗВЕСТНО, facts доступны.
4. `clear-long`: дополнительно удалить долговременные facts; на все 6 вопросов ожидается НЕИЗВЕСТНО.

Каждый вопрос получает независимый запрос с копией одного и того же состояния этапа. Ответы probes не дописываются в память. Поэтому прежний ответ модели не возвращает удалённые сведения. Очистка накопительная, а не восстановление полного состояния перед каждой абляцией. В обычном чате факт может оставаться доступным из другого слоя/сохранившихся реплик: очистка одного слоя не удаляет дубликаты из других.

## Управление слоями обычного ассистента

В /chat выбрать Layered, сохранить настройки. Отдельными кнопками сохранить рабочую память и долговременные facts (JSON-объекты со строковыми значениями), либо очистить каждый слой. Обычная отправка сообщения пополняет только историю. В трассе ответа отображаются оценки токенов каждого слоя. Оба агента direct/tools используют эти правила.

CLI:

```text
/memory Layered
/working {"task":"LAB-118","export":"TSV"}
/longterm {"owner":"Марина Соколова","budget":"420000"}
/layers
/forget-layer short
/forget-layer working
/forget-layer long
```

Команды /working и /longterm заменяют соответствующий словарь целиком; чтобы сохранить прежние ключи, включить их в новый объект. /reset очищает все слои. При создании ветки копируются все слои без общей изменяемой памяти. Невалидный JSON/повтор ключей/нестроковые значения отклоняются до записи.

## Оценивание и токены

Детерминированное сравнение нормализует ответ и ожидание: регистр, пробелы и пунктуация игнорируются, последовательность букв/цифр должна совпадать полностью. Значение не включено в вопрос, удалённые значения не передаются. Сохраняются исходные ответы для ручной проверки.

Вклад каждого слоя — локальная оценка TokenUsageCalculator с обрамлением сообщений; это не точная токенизация конкретной модели. Системная инструкция/текущий вопрос вне суммы слоёв. API usage учитывается для всего запроса отдельно. Н/д не заменяется нулём; стоимость определяется общим RunMetricsReader по снимку тарифов. Наличие ошибок качества не делает завершённый протокол транспортной ошибкой; незавершённый/пустой ответ, ошибка API или отмена оставляют неполный отчёт.
