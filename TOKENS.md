# Подсчёт токенов в диалоге

После каждого ответа консоль показывает четыре оценки контекста: текущий запрос, историю до запроса, полный первый промпт и историю после ответа. Для каждого вызова модели агент также печатает `prompt_tokens` и `completion_tokens`, которые вернул провайдер. В агенте с инструментами usage суммируется по всем вызовам модели за ход; трасса показывает каждый вызов отдельно.

## Что означают числа

- **Текущий запрос, история, контекст** — локальные приблизительные оценки. Счётчик ориентируется на длину слов: примерно 1 токен на 4 символа ASCII или на 2 символа кириллицы, отдельно учитывает знаки препинания, границы сообщений и схемы инструментов. Точный разбор токенизатора конкретной модели отличается.
- **Usage API** — фактические количества из ответа провайдера. `prompt_tokens` включает отправленные системные инструкции и историю; `completion_tokens` — созданный моделью ответ. В цикле с инструментами складываются значения всех запросов к модели.
- **Стоимость** — расчёт по сохранённому снимку тарифов из [BENCHMARK-DAY-5.md](BENCHMARK-DAY-5.md), в рублях за миллион токенов. Для неизвестной модели выводится `н/д`. Снимок тарифов может устареть.
- Сводка usage по диалогу записывается в JSON полезную нагрузку сообщения ассистента. Старые сообщения без этой метаинформации учитываются в оценке истории, но не в накопительном usage.

## Сравнение диалогов

1. Введите `/new Короткий`, отправьте короткий вопрос, затем `/tokens`. Запишите приблизительный размер истории и фактические токены ответа API.
2. Введите `/new Длинный`, отправьте несколько длинных сообщений с подробными ответами. После каждого хода сравнивайте размер истории и `prompt_tokens`: весь предыдущий контекст отправляется повторно, поэтому входные токены и расчётная стоимость следующих ходов обычно растут. Вывод показывает стоимость текущего хода и сумму по сохранённым ходам.
3. Для большой вставки введите `/paste`, вставьте текст (включая переносы строк) и завершите отдельной строкой `/send`. Для отмены используйте `/cancel`. Продолжайте длинный диалог или вставьте большой текст, пока контекст не превысит ограничение выбранной модели. Провайдер отклонит запрос; консоль покажет локальную оценку промпта и сообщение об ошибке. Ответа не будет, неуспешный ход не сохранится. `max_tokens` ограничивает длину ответа и сам по себе не увеличивает окно контекста.

Точное число, при котором произойдёт отказ, зависит от модели, системного промпта, схем инструментов и служебных токенов провайдера. Поэтому локальная оценка служит для сравнения роста, а фактические usage и сообщение модели — для проверки результата.
