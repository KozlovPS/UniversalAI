# Архитектура UniversalAI

```text
Program.cs
  └─ Application/UniversalAIApplication.cs  — выбор режима и сборка зависимостей
       ├─ ConsoleApp/                        — ввод, цикл чата и обработчики slash-команд
       ├─ Services/Agents/                   — агент, реестр и цикл вызова инструментов
       ├─ Services/ChatService.cs            — история, запрос к провайдеру, сохранение хода
       ├─ Services/ContextCompressionService.cs — summary и последние исходные ходы
       ├─ Services/ConversationService.cs    — операции с диалогами и сообщениями
       ├─ Services/Providers/                — выбор подключённого AI-провайдера
       ├─ Providers/                          — протоколы GigaChat и OpenAI-compatible
       ├─ Core/                               — модели запросов и проверка возможностей
       ├─ Data/                               — EF Core контекст и сущности SQLite
       └─ Benchmarks/                         — независимые эксперименты Day-3/4/5/9
```

## Границы ответственности

- `Program.cs` только запускает приложение.
- `UniversalAIApplication` является composition root: создаёт БД, провайдеры и службы, затем выбирает консольный или benchmark-режим.
- `ConsoleChatApplication` управляет интерактивным циклом и отображает ответы.
- `ConsoleCommandRouter` передаёт slash-команды специализированным обработчикам в `ConsoleApp/Commands`.
- `ChatService` готовит контекст из системного промпта и истории, вызывает текущий провайдер и сохраняет успешный ход. Его можно переиспользовать из другого интерфейса.
- `ToolCallingAgent` собирает историю, передаёт схемы функций провайдеру, выполняет запрошенные локальные инструменты и повторяет запрос до финального ответа. Полная последовательность сообщений хода, включая вызовы функций и их результаты, сохраняется в SQLite как JSON и восстанавливается при продолжении диалога; трасса также возвращается вместе с результатом для отображения интерфейсом.
- `IAgent` задаёт общий контракт агента, а `AgentRegistry` разрешает агента по ID. Консоль выбирает его командой `/agent`, ID сохраняется в диалоге; новый агент добавляется реализацией `IAgent` и регистрацией в composition root.
- `ConversationService` занимается только хранением и настройками диалогов.
- `ContextCompressionService` используется обоими агентами. Перед очередным ходом он заменяет старую часть истории накопительным summary из отдельной таблицы `ContextSummaries`. Summary обновляется отдельным запросом к текущей модели без инструментов; предыдущая память объединяется только с новыми старыми сообщениями. Граница проходит между целыми пользовательскими ходами. Исходный журнал остаётся в `ChatMessages` для отключения сжатия и сравнения, но покрытая часть не отправляется в обычный запрос. Usage сжатия хранится отдельно от usage ответов.
- Каждый benchmark остаётся отдельным классом; `BenchmarkCommand` отвечает за выбор по ID.

Новая консольная команда добавляется отдельным `IConsoleCommandHandler` и регистрируется в `UniversalAIApplication`. Новый benchmark получает собственный класс с `RunAsync` и одну запись в `BenchmarkCommand`.

Day-9 добавляет воспроизводимый эксперимент на 30 сообщениях и 13 заранее заданных деталях. Подробности запуска и методики: `BENCHMARK-DAY-9.md`. Офлайн-проверки: `dotnet run -- --benchmark day9 --self-test`.
